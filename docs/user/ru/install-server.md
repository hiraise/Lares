# Установка семейного сервера

Lares хранит данные семьи на вашем собственном сервере. Эта инструкция поможет поднять его на арендованном
виртуальном сервере (VPS) с помощью Docker Compose. Понадобится около часа и умение выполнять команды в терминале
Linux по SSH (достаточно копировать их отсюда).

На сервере работают четыре части: сам сервер Lares, база данных PostgreSQL, **Caddy** (сам получает и продлевает
HTTPS-сертификат) и, по желанию, **ntfy** — для мгновенных уведомлений.

## Что понадобится

- **VPS**: 1 vCPU, 2 ГБ памяти, 20 ГБ диска, Ubuntu 24.04 или Debian 12, процессор x86_64 или ARM64. Для одной семьи
  хватит и 1 ГБ памяти, но впритык. Выбирайте дата-центр поближе к семье — приложение будет отзывчивее.
- **Домен**, которым вы управляете, например `example.com`. Сервер семьи получит поддомен, например `family.example.com`.
- **Открытые порты 80 и 443** на VPS (загляните и в настройки файрвола у хостера).
- **Docker** с плагином Compose (установка ниже).

## 1. Записи DNS

У регистратора домена или в панели DNS создайте записи:

| Имя | Тип | Значение | Зачем |
| --- | --- | --- | --- |
| `family.example.com` | A (и AAAA, если у VPS есть IPv6) | IP-адрес VPS | обязательно |
| `ntfy.family.example.com` | A (и AAAA) | тот же IP-адрес | только для мгновенных уведомлений |

Изменения DNS расходятся от нескольких минут до нескольких часов. Проверить можно командой `ping family.example.com` —
она должна показать адрес вашего VPS.

## 2. Установка Docker

Подключитесь к VPS по SSH и выполните:

```sh
curl -fsSL https://get.docker.com | sudo sh
docker compose version
```

Вторая команда должна вывести номер версии. Дальнейшие команды выполняйте от root или через `sudo`.

## 3. Файлы конфигурации

Положите на сервер папку `deploy` из репозитория проекта, например в `/opt/lares`:

```sh
sudo git clone <адрес репозитория проекта> /opt/lares
cd /opt/lares/deploy
```

## 4. Настройка

```sh
cp .env.example .env
chmod 600 .env
openssl rand -hex 24      # выведет случайный пароль
nano .env
```

В файле `.env` укажите:

- `LARES_DOMAIN` — домен сервера, например `family.example.com`;
- `POSTGRES_PASSWORD` и `LARES_DB_PASSWORD` — сгенерированный пароль, **одинаковый в обеих строках**.

Остальные настройки необязательны, они описаны в самом файле. Никому не показывайте `.env`: в нём пароль от базы.

## 5. Запуск

```sh
docker compose up -d
docker compose ps
```

Через минуту все сервисы должны быть в состоянии `running` (а сервер — `healthy`). Откройте в браузере
`https://family.example.com/health/ready` — должен появиться ответ `{"status":"ok"}`, и соединение должно быть защищённым.

## 6. Код настройки

Новый сервер защищён одноразовым кодом настройки, чтобы никто посторонний не успел занять его раньше вас:

```sh
docker compose logs server | grep "Setup code"
```

Код состоит из 10 букв и цифр. Можно заранее задать свой — строкой `LARES_SETUP_CODE` в `.env`.

## 7. Приложение и создание семьи

1. Установите APK Lares на Android-телефон (скачайте его со страницы релизов проекта; когда Android спросит,
   разрешите установку приложений из этого источника).
2. Откройте приложение и введите **Адрес сервера**: `https://family.example.com`.
3. Приложение увидит, что сервер новый, и откроет экран **Новая семья**. Введите код настройки, название семьи,
   часовой пояс, валюту, язык семьи, а затем своё имя, логин и пароль администратора. Нажмите **Создать семью**.
4. Остальных пригласите прямо из приложения: **Ещё** → **Семья**. Каждый сканирует QR-код приглашения или вводит его
   код; детям можно завести аккаунт без пароля.

## Резервные копии

Все данные семьи лежат в базе. Делайте копию каждый день и храните её **не только** на этом сервере: если VPS
пропадёт, копия на нём пропадёт вместе с ним.

Сделать копию прямо сейчас:

```sh
/opt/lares/deploy/scripts/backup.sh
```

Скрипт создаёт файл `deploy/backups/lares-ГГГГММДД-ЧЧММСС.dump` и хранит 14 последних копий.

Чтобы копия делалась каждый день в 03:00, добавьте строку через `sudo crontab -e`:

```
0 3 * * * /opt/lares/deploy/scripts/backup.sh >> /var/log/lares-backup.log 2>&1
```

Регулярно забирайте копии к себе, например на домашний компьютер:

```sh
rsync -av root@family.example.com:/opt/lares/deploy/backups/ ~/lares-backups/
```

В копиях все данные семьи, включая местоположение и финансы, — берегите их так же, как сам сервер.

## Восстановление

```sh
/opt/lares/deploy/scripts/restore.sh /opt/lares/deploy/backups/lares-20261023-030000.dump
```

Скрипт попросит подтверждение, заменит **все** текущие данные данными из копии и перезапустит сервер. Телефоны заметят
восстановление при следующей синхронизации и сами заново загрузят данные. То, что попало на сервер после создания
копии, будет потеряно; изменения, которые ещё ждали отправки на телефоне (сделанные без интернета), отправятся заново.

Переезд на новый VPS: установите всё по шагам 1–5 с тем же `.env`, перенесите последнюю копию и восстановите её.

## Обновление

Сначала сделайте резервную копию, затем:

```sh
cd /opt/lares/deploy
git pull
docker compose pull
docker compose up -d
```

При запуске сервер сам обновит структуру базы. Если хотите обновляться только тогда, когда сами решите, укажите
версию в `.env` (`LARES_VERSION=0.1.0`) и меняйте её вручную.

## Мгновенные уведомления (по желанию)

Без этого шага уведомления тоже приходят, но с задержкой до 15 минут. Со своим сервером ntfy они приходят за секунды —
и по-прежнему без сервисов Google.

1. Создайте DNS-запись `ntfy.family.example.com` (шаг 1).
2. В `.env` укажите `LARES_CADDYFILE=Caddyfile.push`. Если адрес ntfy не совпадает с `ntfy.` + ваш домен,
   задайте ещё `LARES_NTFY_DOMAIN`.
3. Запустите с профилем `push` и один раз откройте анонимный доступ только к темам для push-уведомлений:

   ```sh
   docker compose --profile push up -d
   docker compose exec ntfy ntfy access '*' 'up*' read-write
   ```

4. Во всех следующих командах `docker compose` добавляйте `--profile push` (или пропишите `COMPOSE_PROFILES=push` в `.env`).
5. Каждый член семьи настраивает приложение ntfy на своём телефоне:
   [Мгновенные уведомления через ntfy](instant-notifications.md).

Сервер ntfy принимает только темы самого приложения — посторонние не смогут использовать его для чего-то ещё.

## Если на сервере уже есть веб-сервер

Если порты 80 и 443 уже заняты nginx или Traefik, уберите сервис `caddy` и настройте в своём веб-сервере проксирование
`family.example.com` на контейнер `server`, порт 8080 (а `ntfy.…` — на контейнер `ntfy`, порт 80). Передавайте
заголовок `X-Forwarded-For`.

## Если что-то не работает

- **Адрес не открывается или браузер ругается на сертификат.** Caddy получит сертификат, только когда
  `family.example.com` указывает на этот VPS, а порты 80 и 443 доступны из интернета. Проверьте `ping family.example.com`,
  файрвол у хостера и `ufw status`, затем посмотрите `docker compose logs caddy`.
- **DNS ещё не обновился.** Подождите и попробуйте снова — Caddy повторяет попытки сам. Ускорить можно командой
  `docker compose restart caddy`.
- **Приложение пишет, что код настройки неверный.** Скопируйте его заново из `docker compose logs server | grep "Setup code"`:
  без `LARES_SETUP_CODE` код меняется при каждом перезапуске.
- **Сервер постоянно перезапускается.** Смотрите `docker compose logs server`. Чаще всего причина — разные значения
  `POSTGRES_PASSWORD` и `LARES_DB_PASSWORD`. Учтите: если поменять `POSTGRES_PASSWORD` позже, пароль уже созданной
  базы не изменится.
- **Мгновенные уведомления не приходят.** Проверьте, что `https://ntfy.family.example.com` открывается в браузере, что
  команда `ntfy access` была выполнена, и пройдите шаги на телефоне из [инструкции по ntfy](instant-notifications.md).
